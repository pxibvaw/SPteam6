# 바른자리 앱 연결 및 확인

## Android Studio 작업본

저장소를 내려받은 뒤 `app/` 폴더를 Android Studio 프로젝트로 연다.
CSV를 추가했던 별도 로컬 작업본과 혼동하지 않도록 현재 프로젝트 경로와 Git 브랜치를 확인한다.
앱 연동 수정은 `app` 브랜치에서 확인한다.

## 세 가지 데이터

- **MOCK**: 서버가 시나리오에 따라 생성하는 모의 센서 데이터. 센서 없이 API·화면 흐름을 확인한다.
  기본 AI 엔진의 결과는 시나리오 라벨과 다를 수 있다. 예측 가능한 화면 검증에는 `--engine fake`를 사용한다.
- **실험 CSV**: 이전 실험에서 저장한 기록. 실시간 데이터가 아니며 MOCK 서버가 자동으로 읽지 않는다.
  보관한 CSV는 7채널이고 현재 API는 6채널이므로 임의로 변환하거나 실시간 센서 순서로 해석하지 않는다.
- **REAL**: Pi에 연결된 센서의 현재 측정값과 AI 판단. 실제 센서 동작은 이 모드에서 검증한다.

## Pi 연결 후 실행

1. Pi와 앱을 설치할 휴대폰을 같은 Wi-Fi에 연결한다. Pi에서 `hostname -I`로 주소를 확인한다.
   앱 기본 주소는 `http://192.168.1.9:8000`이다.
2. **최신 main 서버 코드가 있는 Pi 저장소 루트에서** 먼저 MOCK 서버를 실행한다.
   ```sh
   python -m hardware.server.mock_server --mode mock --engine fake --host 0.0.0.0 --port 8000
   ```
3. 휴대폰 브라우저에서 `http://192.168.1.9:8000/status`를 열어 `mode: mock`을 확인한다.
   접속이 안 되면 앱 실행 전에 Wi-Fi·IP·서버 실행·포트를 확인한다.
4. 앱에서 습관 선택 → 서버 주소 입력 → 연결 → 기준 자세 설정 → 홈으로 이동한다.
   측정을 시작하고 ‘예시 데이터’, ‘판정 대기 중’, 확정 자세, 일시정지·재개·종료, 리포트를 확인한다.
5. Pi 터미널에서 MOCK 서버를 Ctrl+C로 종료하고 **같은 포트에 하나의 서버만** 실행한다.
   ```sh
   python -m hardware.server.mock_server --mode real --host 0.0.0.0 --port 8000
   ```
   Pi 카메라를 사용하는 환경은 서버 담당자가 지정한 카메라 옵션(예: `--camera picam`)을 함께 사용한다.
6. `/status`의 `mode: real`을 확인하고 앱에서 다시 연결해 기준 자세를 측정한다.
   센서 상태가 정상인지, 약 5초 후 자세가 반영되는지 확인한다.

앱에서 MOCK/REAL 스위치를 조작하는 방식이 아니다. **서버 실행 모드**를 바꾸면 앱이 `/status.mode`로 구분한다.
센서가 없어도 REAL이라고 속여 표시하거나 서버 연결 실패 시 예시값으로 대체하지 않는다.

## APK 및 알려진 제한

- 확인용 APK: `app/app/build/outputs/apk/debug/Barunjari-Pi-ready-debug.apk` (저장소 루트 기준).
  디버그 서명 APK이며 스토어 배포용이 아니다.
- 인터넷 연결 권한과 Pi 주소의 HTTP 허용을 포함한다. IP가 바뀌면 주소 입력 외에
  `network_security_config.xml`의 허용 대상도 확인한다. HTTPS는 기본 허용된다.
- 로컬 MOCK 검증용 `127.0.0.1`은 debug 리소스에서만 허용한다. 에뮬레이터에서는
  `adb reverse tcp:18000 tcp:18000` 후 PC의 MOCK 서버에 접근할 수 있다.
- 현재 자세·세션은 응답 후 1초 간격, 리포트는 5초 간격으로 조회한다.
  서버 기록 집계의 저장 지연은 별개이다. `pending`이 있을 때만 판정 대기를 표시한다.
- `unknown`은 정상으로 처리하지 않는다. 정상 비율은 서버가 반환하는 값을 사용한다.
- 설정 동기화·CSV 내보내기·주변 기기 검색 API는 서버에 아직 없다.
- 에뮬레이터의 `System UI isn't responding`/`offline`은 Pi 미연결과 별개이다.
  실제 휴대폰 APK 검증을 우선하고, 에뮬레이터를 새로 시작할 때는 Device Manager의 Cold Boot를 시도한다.
  Wipe Data, 앱 삭제, 데이터 초기화는 하지 않는다.

## 검증 구분

MOCK 서버 API 검증, Android 빌드·단위 테스트, 기기 UI 전체 검증, REAL 센서 검증을 별도로 기록한다.
실제 Pi를 연결하기 전에는 REAL 검증 완료로 판단하지 않는다.
